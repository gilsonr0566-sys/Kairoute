# Kairoute rules registry: one rule for each class of bug

Richard, Nov 23 2026: "We have talked many times there needs to be rules for every error found ... We are going to keep
battling issues if we are not creating app wide rules to correct issues found. Everything else is layers and leak plugging."

This file is the one list of app-wide rules. A rule is written for a **whole class** of bug, never for one place or one
trip ("every name on screen is in the traveler's language", not "Kyoto's station names in English"). The release gate
reads this file (`tools/truth/rules-check.cjs`, in part 1) and fails the release when any of these is not true:

1. **Every rule is enforced or has a dated owner.** An ENFORCED rule names at least one check the release gate runs on
   every release (`tools/...`) and at least one **planted bug** that proves the check fires: a planted defect in the
   engine (`some-defect-id`, from `tools/truth/mutants.cjs` or `sight-mutants.cjs`), a planted screen bug
   (`screen: rule name`, from `tools/truth/screen-rule-proof.cjs`, which plants one bug for every screen rule), or a check
   that plants its own bad input on every run (listed in rules-check.cjs). A rule not yet there says what is missing,
   names its owner, and gives a date at most 7 days ahead; after that date the release fails.
2. **Every escaped bug has a class rule.** Each row of the escaped-bug log (`docs/qa/escapes.md`) is listed under a rule
   below. A new bug with no rule fails the release, so a fix can't be recorded without saying which class it belongs to.
3. **Every fix names its rule.** Each commit that changes the app or the helper (`src/`, `worker/`) after
   2026-11-23 23:30 UTC carries a line `Rule: R-xx` naming a rule in this table (more than one is fine). If the class is new, the
   commit adds the rule here first. A commit made without it can be linked afterwards in `docs/qa/rule-links.md`
   (`<sha> R-xx why`), which is reviewed like any other change.

"Repeat" marks a class that came back after an earlier fix: those are the ones a class rule exists to stop. "Before"
says whether a check covered the **whole class** when its first bug got through: **none**, **partial** (one sample trip,
or the planner's own numbers, or one data source), or **yes**.

Status words: **ENFORCED** (gate check + planted bug, every release), **NO PROOF** (gate check, no planted bug yet),
**OPEN** (no gate check yet). Severity: S1 = could make a traveler miss a ship, train or flight; S2 = wrong or untrue on
screen; P = the checking process itself.
